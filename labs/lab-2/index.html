O problema: trepidação (bounce)

Quando as lâminas de metal do botão se tocam, elas batem e quicam algumas vezes antes de assentar. Para nós, isso dura um instante; para o Arduino, que lê o pino milhões de vezes por segundo, são várias transições HIGH ↔ LOW.

Se o programa conta cada borda de descida como um aperto, um único toque pode virar 2, 3 ou 5 contagens, e um LED que deveria alternar pode terminar no mesmo estado.

Software

O programa só aceita uma mudança se o sinal ficar parado por uma janela de tempo (ex.: 50 ms). Custo zero, mas ocupa lógica no código.

Hardware

Um filtro RC suaviza o sinal antes de chegar ao pino. O código fica simples, mas exige componentes e dimensionamento.

O circuito na bancada

O botão liga o pino D2 ao GND e usa o pull-up interno (INPUT_PULLUP): solto, o pino lê HIGH; apertado, lê LOW. O LED no D8, com resistor de 220 Ω, alterna a cada aperto aceito, e o Monitor Serial mostra a contagem.

Botões reais trepidam, cada um de um jeito. Se 10 apertos derem exatamente 10 na Parte A, aperte de leve ou mais rápido: a trepidação aparece mais nas bordas do movimento.

Montando na protoboard

  1. Encaixe o botão atravessando o canal central da protoboard. Ligue um terminal ao D2 e o terminal do lado oposto ao GND.
  2. Ligue o D8 ao resistor de 220 Ω, o resistor ao ânodo (perna longa) do LED e o cátodo ao GND.
  3. Conecte o Arduino pela USB, abra a Arduino IDE, selecione a placa Arduino Uno e a porta.
  4. Grave o código da Parte A e abra o Monitor Serial em 9600 baud.

Parte A

Contador sem debounce

O programa conta cada borda de descida (HIGH → LOW) como um aperto. Rode, aperte o botão exatamente 10 vezes, com calma, e anote a contagem final do Monitor Serial.

sketch.ino · Parte A
// Lab 2 — Parte A: contador SEM debounce

const int PINO_BOTAO = 2;   // botão entre D2 e GND
const int PINO_LED   = 8;   // LED com resistor de 220 Ω

int contador = 0;
int estadoAnterior = HIGH;   // INPUT_PULLUP: solto = HIGH

void setup() {
  pinMode(PINO_BOTAO, INPUT_PULLUP);
  pinMode(PINO_LED, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int leitura = digitalRead(PINO_BOTAO);
  if (estadoAnterior == HIGH && leitura == LOW) {   // borda de descida = aperto
    contador++;
    digitalWrite(PINO_LED, !digitalRead(PINO_LED));
    Serial.print("Apertos: ");
    Serial.println(contador);
  }
  estadoAnterior = leitura;
}
Se a contagem passar de 10, você viu a trepidação acontecer. Se der exatamente 10, aperte de novo algumas vezes: a trepidação é aleatória e nem todo aperto quica.

Parte B

Debounce por software

A ideia: toda vez que a leitura muda, o programa zera um cronômetro. Só quando a leitura fica parada por mais que a janela de debounce ela é aceita como o novo estado do botão. Como usa millis() e não delay(), o loop() continua livre para outras tarefas.

sketch.ino · Parte B
// Lab 2 — Parte B: contador COM debounce por software

const int PINO_BOTAO = 2;
const int PINO_LED   = 8;
const unsigned long JANELA_DEBOUNCE = 50;   // ms

int contador = 0;
int estadoEstavel = HIGH;          // último estado aceito
int ultimaLeitura = HIGH;          // última leitura bruta
unsigned long instanteMudanca = 0;  // quando a leitura mudou pela última vez

void setup() {
  pinMode(PINO_BOTAO, INPUT_PULLUP);
  pinMode(PINO_LED, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  int leitura = digitalRead(PINO_BOTAO);

  if (leitura != ultimaLeitura) {      // o sinal mexeu: reinicia o cronômetro
    instanteMudanca = millis();
  }

  if (millis() - instanteMudanca > JANELA_DEBOUNCE && leitura != estadoEstavel) {
    estadoEstavel = leitura;             // ficou parado por mais que a janela: aceita
    if (estadoEstavel == LOW) {        // o novo estado é "apertado"
      contador++;
      digitalWrite(PINO_LED, !digitalRead(PINO_LED));
      Serial.print("Apertos: ");
      Serial.println(contador);
    }
  }
  ultimaLeitura = leitura;
}
Teste de aceitação: aperte o botão 10 vezes. A contagem deve ser exatamente 10 e o LED deve alternar a cada aperto. Depois, experimente JANELA_DEBOUNCE = 1 e veja a trepidação voltar.

Parte C

Debounce por hardware: filtro RC

No lugar do pull-up interno, um resistor externo R carrega um capacitor C ligado ao pino. O botão descarrega o capacitor quase na hora (por um resistor pequeno, de 100 Ω, que protege os contatos). Quando o botão quica e abre por um instante, o capacitor não tem tempo de carregar até o limiar de HIGH, e o pino continua lendo LOW.

Rede RC no pino D2

As contas

Constante de tempo: τ = R · C

Carga do capacitor: V(t) = Vcc · (1 − e−t/τ)

Tempo para chegar a uma tensão V: t = −τ · ln(1 − V/Vcc)

O ATmega328P considera HIGH acima de VIH = 0,6 · Vcc = 3 V e LOW abaixo de VIL = 0,3 · Vcc = 1,5 V, com uma entrada Schmitt trigger (histerese) entre os dois. O filtro funciona se o capacitor levar mais tempo para chegar a 3 V do que a trepidação dura.

Montagem

  1. Desligue o fio que ia do botão ao GND.
  2. Resistor de 10 kΩ do 5 V ao D2.
  3. Capacitor de 1 µF do D2 ao GND. Se for eletrolítico, a perna negativa (lado da faixa) vai no GND.
  4. Botão do D2 ao GND, passando pelo resistor de 100 Ω.
  5. Grave o código da Parte A trocando INPUT_PULLUP por INPUT e conte 10 apertos.

Identificação
1 Contextualizar

Antes de mexer no código, escreva com suas palavras:

  • o objetivo: contar apertos de um botão de forma confiável;
  • o comportamento esperado: cada aperto soma exatamente 1 e alterna o LED;
  • o critério de aceitação: 10 apertos geram contagem 10 no Monitor Serial, e o filtro RC escolhido leva mais tempo para chegar a VIH do que a trepidação dura;
  • o que você vai delegar à IA e o que pretende fazer sozinho.
2 Consultar

Faça à IA uma pergunta delimitada sobre um ponto que você não domina. Uma pergunta delimitada pede explicação ou hipótese, não o código pronto. Exemplo: “Por que o debounce com millis() não trava o programa e o com delay() trava?”

3 Confrontar

Escolha uma afirmação técnica da resposta e confira contra uma fonte primária:

  • o exemplo oficial Debounce da documentação do Arduino, que usa uma janela de 50 ms;
  • o datasheet do ATmega328P: limiares VIH = 0,6·Vcc e VIL = 0,3·Vcc e entrada com Schmitt trigger;
  • o seu próprio teste na bancada: a contagem das Partes A, B e C.

Diga se a afirmação se confirmou, precisou de ajuste ou estava errada, citando o trecho da fonte ou o resultado do teste. Se você rejeitou ou corrigiu uma sugestão, ela vira o seu ADR (registro de decisão).

4 Construir

Monte e rode as três partes na bancada e registre a contagem do Monitor Serial após 10 apertos em cada uma.

5 Comprovar sem IA

Responda sozinho, sem consultar a IA. Na correção, o professor pode pedir que você explique qualquer resposta.

5.1 Qual é a constante de tempo τ de um filtro com R = 10 kΩ e C = 1 µF?

5.2 Na Parte A, 10 apertos geraram mais de 10 contagens. Qual é a causa?

5.3 Com R = 10 kΩ e C = 1 µF, quanto tempo após soltar o botão o capacitor leva para carregar de 0 V até VIH = 3 V (Vcc = 5 V)?

5.4 Tarefa de transferência: um botão de outro fornecedor trepida por até 15 ms. Mantendo R = 10 kΩ, qual é o menor capacitor comercial que garante que o pino só chegue a VIH depois que a trepidação acabou?
